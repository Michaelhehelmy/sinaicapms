## Notes for the Phase 4/5 doc edit

1. **The `400-guard` half of the runbook phrase is the imprecise half, not a live
   defect.** `/api/me` was expected by the phrasing to answer an auth guard, and
   instead answered `200` — which is the **designed** behaviour, stated in the
   source: `backend/src/index.js:616-617` reads *"Mixed visibility: GET is public
   (R-9 — graceful 200 without tenant context)"*, with `meScope` (`:619-624`)
   routing `GET` to `resolveScope({ public: true })`. So `200` here is
   correct-by-design and must **not** be written up as an unexpected finding.
2. The `200` for `/api/me` did **not** come from a static-asset fallback that
   swallowed an unrouted API path: `app/public/_routes.json` explicitly
   `exclude`s `/api/*` from the `/*` include, so the request reached the SSR
   function and its backend service binding (`API_BACKEND`, `app/wrangler.toml`).
   Worth stating, because a `200` on an `/api/*` path is otherwise a plausible
   fallback artifact and would have made this row ambiguous.
3. O-7's code half was already verified by the B+C pass
   (`gaps-triage-BC-2026-10-06.md:119`) — `/api/me` really is a mounted family.
   This probe adds only the runtime codes, so the entry can now move
   `UNVERIFIED (external)` → resolved rather than being re-audited.
4. `acaciacamp.com/admin` answering `200` unauthenticated is consistent with the
   SPA host serving its shell; the runbook's follow-up instruction ("open
   `acaciacamp.com/admin` and confirm the Settings panel loads with no chunk
   404") is a **browser** check that a status code cannot satisfy and remains
   unverified — no request in this probe can close it.
